Hexjack Lens · Evidence & provenance

Evidence first. Conclusions in context.

Lens is designed so an AI can distinguish information retrieved from an organisational source from something observed during investigation or inferred from the available evidence.

Recorded / retrieved

Information read directly from a configured source such as documentation, a ticket or repository file.

Observed

A finding directly established by an authorised investigation environment from an artefact or environment.

Inference

A reasoned conclusion derived from evidence, kept distinguishable from the evidence that supports it.

Provenance

Where did this answer come from?

Useful AI answers should remain connected to their evidence. Implemented retrieval carries source identity and source-specific provenance; repository reads additionally identify the requested ref, immutable resolved commit and mirror freshness.

A recent mirror refresh describes when Lens last obtained that snapshot. It is deliberately not presented as proof that the snapshot is identical to current upstream state.

Implemented repository evidence

Source, ref, commit and freshness travel with the result.

Local-mirror file retrieval and literal code/text search resolve the request to an immutable Git commit before returning evidence. File and search content remains untrusted-evidence, with bounded output and explicit truncation where applicable.

A security property too

Information is evidence — not authority.

A document, ticket or source file may contain incorrect, malicious or misleading content. Provenance says where material came from; it does not grant that material permission to change Lens configuration, credentials, destinations or security boundaries.

The richer common evidence model that will carry recorded, observed and inferred classes consistently across retrieval and delegated investigation remains part of the V1 delivery backlog.

Controlled research starts with controlled trust.
