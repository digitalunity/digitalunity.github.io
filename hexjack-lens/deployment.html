Hexjack Lens · Deployment

Your infrastructure. Your boundary.

Lens is designed around an immutable software artifact with organisation-specific configuration, credentials and network policy supplied by the deployment environment.

Immutable application

The same versioned Lens artifact can be used across estates without rebuilding it around customer-specific values.

External secrets

Credentials remain outside the application image and can be managed and rotated by the organisation's approved runtime mechanism.

Controlled network

Lens is designed to operate with explicit source/provider connectivity rather than requiring unrestricted Internet egress.

Container-first

A portable deployment boundary.

The deployment architecture uses an OCI-compatible container as the primary software distribution model, allowing the same application artifact to move from local development to customer-controlled container environments and enterprise orchestration.

A container is packaging and runtime isolation, not a security claim by itself. Host, identity, network, secrets and orchestration controls remain part of the deployment security model.

Restricted environments

No mandatory callback to Digital Unity.

The architecture does not require production Lens installations to contact Digital Unity simply to operate. Controlled artifact transfer and customer/internal registries can support environments where direct access to public infrastructure is inappropriate.

Deployment choices

Keep control where it belongs.

Lens can fit customer-managed or managed-installation models while retaining the same fundamental separation between software, customer configuration and credentials. A future hosted service would require additional architecture around tenant isolation, credential custody and service operation rather than silently weakening those boundaries.

Deployment is part of the security architecture.
