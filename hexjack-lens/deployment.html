Hexjack Lens · Deployment

Your infrastructure. Your boundary.

Hexjack Lens is a deliberately small Go application with an OCI container as its primary distribution model and supported native binaries as a secondary option. Organisation-specific configuration and credentials remain outside the application artifact.

OCI-first

OCI is the portable artifact contract. Docker, Podman, containerd, Kubernetes and OpenShift are runtime or orchestration choices rather than different Lens product builds.

External secrets

Lens resolves logical credential references at runtime, keeping credential material separate from both the application artifact and non-secret topology.

Native option

Supported native Go binaries provide a secondary distribution path for environments where running the application directly is appropriate.

One application

A portable deployment boundary.

The same Lens source and application boundary feeds OCI and supported native distributions. Customer-specific values do not require customer-specific application builds.

A container is packaging and runtime isolation, not a security claim by itself. Host, identity, network, secrets and orchestration controls remain part of the deployment security model.

Restricted environments

No mandatory callback to Digital Unity.

The architecture does not require production Lens installations to contact Digital Unity simply to operate. Controlled artifact transfer, internal registries and native artifact import can support environments where direct access to public infrastructure is inappropriate.

Deployment choices

Keep control where it belongs.

Lens can fit customer-managed or managed-installation models while retaining the same fundamental separation between software, customer configuration and credentials. A future hosted service would require additional architecture around tenant isolation, credential custody and service operation rather than silently weakening those boundaries.

Deployment is part of the security architecture.
